## ☑️ 기본 개념

### ✅ CPU 스케줄링의 필요성과 기본 개념

- 다중 프로그램 운영체제에서 CPU를 효율적으로 사용하여 전체 시스템 생산성을 높임
- 여러 프로세스가 메모리에 동시에 존재할 때, 단일 CPU 코어에서 어느 프로세스가 실행될지 결정해야 함
- 프로세스는 짧은 CPU 버스트와 긴 I/O 버스트를 번갈아 수행하므로, CPU 유휴 시간을 최소화하는 것이 중요함
- 효율적인 스케줄링은 CPU 사용률을 극대화하고 전체 처리량과 응답성을 향상시킴

### ✅ CPU 스케줄러와 그 역할

- 메모리에 있는 준비 상태의 프로세스 중 하나를 선택하여 CPU 코어를 할당함
- 프로세스 제어 블록(PCB)을 관리하며, 각 프로세스의 상태, 우선순위, CPU 버스트 예측 정보를 활용함
- FIFO, 우선순위 큐, 연결 리스트 등 다양한 자료구조를 사용하여 프로세스 선택 알고리즘을 구현함
- CPU가 유휴 상태일 때 준비 큐에서 실행 가능한 프로세스를 찾아 CPU를 점유시킴


### ✅ 선점형과 비선점형 스케줄링

- **`선점형 스케줄링`**: 프로세스가 자발적으로 CPU를 반납하지 않으면 타임 슬라이스 만료나 높은 우선순위 프로세스 도착 시 강제로 CPU를 빼앗음
- **`비선점형 스케줄링`**: 프로세스가 종료되거나 I/O 요청 등으로 자발적으로 CPU를 반납할 때까지 계속 실행됨
    - 문맥 교환 횟수를 줄여 오버헤드를 낮출 수 있음

### ✅ CPU 스케줄링 의사결정 시점

- **실행 → 대기 전환**: I/O 요청이나 기타 이유로 프로세스가 대기 상태로 전환될 때
    - 예: I/O 요청, 자식 프로세스가 종료되기를 기다리는 wait() 호출
- **실행 → 준비 전환**: 인터럽트나 타임 슬라이스 만료 등으로 실행 중인 프로세스가 준비 상태로 전환될 때
    - 예: 인터럽트 발생
- **대기 → 준비 전환**: I/O 완료 등으로 대기 중인 프로세스가 준비 상태로 전환될 때
    - 예: I/O 종료
- **프로세스 종료 시**: 현재 실행 중인 프로세스가 종료되면, 새로운 프로세스가 CPU를 할당받아야 함

> ‘실행 → 대기 전환'와 ‘프로세스 종료’에서만 스케줄링이 발생한 경우, 이러한 스케줄링 방식을 **`비선점`**이라고 함
> 

### ✅ 디스패처

- CPU 코어의 제어를 CPU 스케줄러가 선택한 프로세스에 주는 모듈
- 주요 작업은 한 프로세스에서 다른 프로세스로 문맥을 교환하는 것, 사용자 모드로 전환하는 것, 프로세스 재시작을 위해 올바른 위치로 점프하는 것
- 문맥 교환 과정에서는 현재 실행 중인 프로세스의 PCB에 상태를 저장하고, 다음 프로세스의 PCB에서 상태를 복원함
- 효율적인 디스패처 설계는 문맥 교환 오버헤드를 최소화하여 전체 시스템 성능에 긍정적 영향을 줌
- Linux에서는 vmstat 명령을 통해 문맥 교환 횟수를 모니터링할 수 있으며, /proc 파일 시스템을 통해 개별 프로세스의 자발적 및 비자발적 문맥 교환 횟수를 확인할 수 있음
- 자발적 문맥 교환은 I/O 요청 등으로 인해 프로세스가 CPU 제어를 자발적으로 포기할 때 발생함
- 비자발적 문맥 교환은 타임 슬라이스 만료나 높은 우선순위 프로세스에 의해 선점될 때 발생함
- 디스패처는 빠르고 효율적으로 동작해야 하며, 디스패치 지연이 짧을수록 시스템의 응답성이 향상됨


### ✅ 스케줄링 평가 기준

- **CPU 이용률** : CPU를 가능한 한 바쁘게 유지하는 정도
- **처리량** : 단위 시간당 완료되는 프로세스 수
- **총처리 시간** : 프로세스 제출 시각부터 완료 시각까지 걸린 전체 시간(대기 시간, CPU 실행 시간, I/O 시간이 포함됨)
- **대기 시간** : 준비 큐에서 프로세스가 기다린 총 시간
- **응답 시간** : 대화형 시스템에서 사용자의 요청 후 처음 응답이 시작되기까지 걸리는 시간

### ✅ CPU 스케줄링 문제

- 준비 큐에 있는 프로세스 중 어느 프로세스에 CPU 코어를 할당할지 결정하는 문제

## ☑️ 주요 CPU 스케줄링 알고리즘

### ✅ 선입 선출 (FCFS) 스케줄링

- 프로세스들이 도착한 순서대로 CPU를 할당받으며 FIFO 큐로 구현됨
- 구현이 매우 간단하고 이해하기 쉬움
- 긴 CPU 버스트를 가진 프로세스가 먼저 도착하면, 이후 도착한 짧은 프로세스들이 모두 긴 대기 시간을 겪음
- 이러한 컨보이 효과로 전체 시스템의 응답성과 처리량이 저하될 수 있음
- FCFS는 일괄 처리 시스템에서는 효과적이나 대화형 시스템에서는 부적합함

### ✅ 최단 작업 우선 (SJF) 스케줄링

- 각 프로세스의 다음 CPU 버스트 길이가 가장 짧은 프로세스에 CPU를 할당함
- 평균 대기 시간을 최소화하는 최적의 알고리즘으로 평가됨
- 실제 구현에서는 다음 CPU 버스트 길이를 정확히 알 수 없으므로, 과거 측정값에 기반한 지수 평균 기법을 사용함
    - 예측 공식: τₙ₊₁ = α·tₙ + (1-α)·τₙ (여기서 α는 최근 값과 과거 값의 가중치를 조절)
- 짧은 작업을 우선 처리하여 전체 대기 시간을 줄이는 장점이 있음
- 예측 오차로 인한 성능 저하 및 긴 작업의 기아 현상 위험이 존재함
- 선점형 버전은 SRTF(Shortest Remaining Time First)로 불리며, 현재 실행 중인 프로세스가 새로 도착한 짧은 작업에 의해 선점될 수 있음
- SJF는 이상적인 조건에서는 최적이나, 실제 환경에서는 구현의 복잡성과 예측의 어려움이 있음

### ✅ 라운드 로빈 (RR) 스케줄링

- 각 프로세스에 고정된 시간 할당량(타임 슬라이스)을 부여하여 순환적으로 CPU를 할당하는 선점형 알고리즘임
- 준비 큐는 원형 큐로 관리되며, 프로세스가 한 타임 슬라이스 동안 실행된 후 남은 작업이 있으면 큐의 뒤로 이동함
- 대화형 시스템에서 응답 시간을 개선하는 데 효과적임
- 타임 슬라이스가 너무 짧으면 문맥 교환 오버헤드가 증가하고, 너무 길면 FCFS와 유사한 결과가 발생함
- 적절한 시간 할당량의 선택이 시스템 성능에 매우 중요함
- RR은 모든 프로세스에 공평하게 CPU 시간을 분배하여 기아 현상을 방지함
- 여러 번 선점되면서 평균 대기 시간이 길어질 수 있는 단점이 있음

### ✅ 우선순위 기반 스케줄링

- 다단계 큐 스케줄링은 프로세스를 실시간, 시스템, 대화형, 배치 등 유형별로 분리하여 각 큐에 할당하고, 각 큐마다 다른 스케줄링 알고리즘(예: FCFS, RR 등)을 적용함
- 각 큐는 고정 우선순위를 가지며, 높은 우선순위 큐에 프로세스가 존재하면 낮은 우선순위 큐의 프로세스는 실행되지 않음
- 다단계 피드백 큐 스케줄링은 프로세스가 실행 중 자신의 CPU 사용량에 따라 큐 사이를 이동할 수 있도록 허용함
- 짧은 CPU 버스트를 가진 프로세스는 높은 우선순위 큐에서 빠르게 처리되고, 긴 CPU 버스트를 가진 프로세스는 점차 낮은 우선순위 큐로 강등됨
- 대기 시간이 길어지면 프로세스가 높은 우선순위 큐로 승격되어 기아 현상을 방지함
- 큐의 개수, 각 큐의 스케줄링 방식, 승격 및 강등 기준 등 여러 매개변수로 세밀하게 조정할 수 있음

### ✅ 다단계 큐 및 다단계 피드백 큐 스케줄링

- 다단계 큐 스케줄링은 프로세스를 실시간, 시스템, 대화형, 배치 등 유형별로 분리하여 각 큐에 할당하고, 각 큐마다 다른 스케줄링 알고리즘(예: FCFS, RR 등)을 적용함
- 각 큐는 고정 우선순위를 가지며, 높은 우선순위 큐에 프로세스가 존재하면 낮은 우선순위 큐의 프로세스는 실행되지 않음
- 다단계 피드백 큐 스케줄링은 프로세스가 실행 중 자신의 CPU 사용량에 따라 큐 사이를 이동할 수 있도록 허용함
- 짧은 CPU 버스트를 가진 프로세스는 높은 우선순위 큐에서 빠르게 처리되고, 긴 CPU 버스트를 가진 프로세스는 점차 낮은 우선순위 큐로 강등됨
- 대기 시간이 길어지면 프로세스가 높은 우선순위 큐로 승격되어 기아 현상을 방지함
- 큐의 개수, 각 큐의 스케줄링 방식, 승격 및 강등 기준 등 여러 매개변수로 세밀하게 조정할 수 있음

- 프로세스를 실시간, 시스템, 대화형, 배치 등 유형에 따라 서로 다른 큐에 분리하고, 각 큐마다 서로 다른 스케줄링 알고리즘(예: FCFS, RR 등)을 적용함
- 큐 간에는 고정 우선순위나 CPU 시간 할당량 분배 방식 등을 사용하여 스케줄링함
