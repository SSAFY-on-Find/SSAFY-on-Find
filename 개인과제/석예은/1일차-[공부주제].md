# 📘 Today I Learned: Kubernetes 기초 및 아키텍처

## 📅 날짜

## 📌 학습 주제
Kubernetes의 기본 개념, 컨테이너 오케스트레이션, 3-Tier 아키텍처와 Kubernetes 환경에서의 구현 방식에 대해 학습하였다.

---

## 📖 1. 전통적인 웹 서비스 구조 vs 컨테이너 기반 구조

### 기존 구조
- **로드 밸런서(Load Balancer)** → 다수의 VM으로 분산
- Auto Scaling Group을 활용해 VM 수를 자동 확장/축소 가능

### 컨테이너 기반 구조 (Kubernetes)
- 로드 밸런서 → Ingress → Pod
- Pod 단위의 오토스케일링 (HPA: Horizontal Pod Autoscaler)
- 노드 단위의 오토스케일링 (NA: Node Autoscaler)

---

## 📖 2. Kubernetes란?

- 수많은 컨테이너를 자동으로 관리해주는 **Container Orchestrator**
- 대표적인 기능:
  - 컨테이너 자동 배포, 복구, 확장
  - 무중단 배포 및 롤백
  - 서비스 디스커버리, 로드 밸런싱
  - 자원 최적화 및 자동 스케일링

---

## 📖 3. 컨테이너(Container) 개념

- 컨테이너 = 실행 환경 (애플리케이션 + 라이브러리 + 설정 등)
- 특징:
  - 이식성 (어디서든 동일한 환경 실행)
  - 격리성 (독립적이고 안전하게 실행)
  - 경량성 (빠르고 효율적)

#### ✅ O/X 퀴즈
- `.exe`, `.jar`, `.war` 파일은 컨테이너가 아니다 ❌
- `Dockerfile`로 컨테이너를 만들 수 있다 ⭕

---

## 📖 4. Docker와 Dockerfile

- **Docker**: 컨테이너 생성/실행/관리를 위한 플랫폼
- Dockerfile 예시:

```Dockerfile
FROM openjdk:17
WORKDIR /app
COPY build/libs/*.jar app.jar
EXPOSE 8080
CMD ["java", "-jar", "app.jar"]

- 실행 명령어:
$ docker build -t my-app:1.0 .
$ docker run -p 80:8080 my-app:1.0

## 📖 5. Kubernetes가 해결하는 문제
- 컨테이너의 배포/확장/복구 자동화
- 무중단 배포, 롤백 기능
- 서비스 디스커버리 및 로드 밸런싱
- 자원 최적화, 자동 스케일링, 셀프힐링(Self-healing)

## 📖 6. Kubernetes Architecture
- Control Plane
    - kube-api-server, etcd, controller manager, scheduler
- Node
    - 각 노드는 kubelet, kube-proxy, 여러 개의 Pod로 구성
- 클러스터 전체는 Cloud Provider API와 연동됨

## 📖 7. 3-Tier Architecture in Kubernetes
- 기존 3계층 아키텍처
    - Presentation (Web)
    - Business/Logic (WAS)
    - Data (DB)
- Kubernetes에서는 각 계층을 Pod 단위로 분리하여 구성
    - 각 Pod는 Worker Node 위에서 실행됨

## 📖 8. 실전 아키텍처 예시
- Kubernetes Engine + Ingress + Web Server + App Server + DB
- Apache HTTP 서버와 Tomcat이 컨테이너로 구동됨
- PostgreSQL 등 DB도 서비스로 분리 가능


## 🧱 9. Monolithic vs Microservice Architecture

| 항목               | Monolithic                              | Microservice (MSA)                    |
|--------------------|------------------------------------------|----------------------------------------|
| 구성 방식          | 모든 기능이 하나의 애플리케이션으로 구성 | 기능 단위로 독립된 서비스(SVC)로 구성 |
| 데이터베이스       | 단일 DB                                   | 서비스 별 개별 DB                     |
| 배포 및 유지보수   | 통합 빌드 및 배포                         | 개별 서비스 단위로 배포 가능           |
| 확장성             | 전체 시스템 단위 확장                     | 서비스 단위 확장 가능                  |

---

## 🔧 10. Microservice Architecture in Kubernetes

- 클라이언트 → DNS → Load Balancer → API Gateway → 각 MSA 컨테이너
- Kubernetes 상에서 각 서비스는 **Pod**로 실행됨
- 데이터베이스도 서비스 별로 분리 가능 (PostgreSQL, MySQL 등 DBaaS)
- CI/CD 파이프라인과 연동하여 자동화된 배포 가능
- 이벤트 스트림(Kafka 등)과 백엔드 시스템 연계 가능

> Kubernetes는 MSA 구조의 유연성과 확장성을 극대화하는 데 필수적인 플랫폼이다.

---

## 🔄 11. DataOps Architecture in Kubernetes

- Kubernetes 기반 데이터 처리 구조
- Web UI + Scheduler + Ops Manager로 DAG 기반 스케줄링 구성
- Worker Pod가 동적으로 생성되어 데이터 흐름 처리
- 다양한 데이터 소스 연동 가능:
  - Data Flow, Hadoop, Legacy System, Object Storage 등
- System Manager와 Data Engineer가 운영 및 제어

> 데이터 처리 파이프라인을 자동화하고, 확장성과 관리 편의성을 확보할 수 있다.

## ☁️ 12. Cloud Native

- **Cloud Native**란?
  - 클라우드 환경에서 애플리케이션을 설계, 구축, 실행하기 위한 접근 방식
  - Kubernetes, CI/CD, DevOps, Microservice 기반 기술들과 밀접한 연관

- 주요 키워드:
  - `continuous`, `delivery`, `devops`, `kubernetes`, `automation`, `elasticity`, `scalability`, `teams`, `resilience`, `infrastructure as code`

- 핵심 특징:
  - **Elasticity**: 수요에 따른 자동 확장/축소
  - **Resilience**: 장애 대응 및 자동 복구
  - **Automation**: 배포, 운영, 모니터링 자동화
  - **Observability**: 모니터링 및 로그 중심의 운영
